## Decisions (answered by the owner, 26 Nov 2026; also in `docs/decisions.md`)

- **S0-1 (A):** the list of changes is the pull-request list joined with the default branch's activity history. A change is a merged pull request, or a commit brought by a `push` or `branch_creation` entry that is not part of a pull request's merge. The walk of `main` stays as a cross-check; any commit neither explains gets a "not covered" line. Where the activity history does not reach back to the period's start (its retention is not documented), that repository gets a "not covered" line for the gap.
- **S0-2 (A):** force pushes are listed in their own section, "History rewritten": the time, the account and the number of commits the force push brought in. Those commits are not counted as changes, and the record says so.
- **S0-3 (A):** logins are printed only from these authenticated actions: opening the pull request, merging it, reviewing it, switching auto-merge on, adding it to a merge queue, and pushing to the default branch (the activity history's account). A commit's author and committer fields, and any login GitHub links to them, are never printed. They are read only as AI markers: a `Co-Authored-By` line, or an author name, that matches the fixed list of coding agents in row 5. Bots are recognised by account id, not by login text.
- **S0-4 (A):** a change with no pull request is one row per commit, as in example `a1b2c3d`. The builder is "no pull request: not shown"; "pushed by" is the account in the activity history. This includes each repository's first push. The totals give both numbers: commits and pushes.
- **S0-5 (A):** the checks on the merged version are the check runs and commit statuses on the pull request's last commit that started before the merge. Where a check of one name ran more than once, the last run is shown. A check that started before the merge and finished after it shows as "not finished at the merge", never as its later result.
- **S0-6 (A):** an approval that is not dismissed counts for the pattern; the row says "on an earlier version" when its commit is not the merged one, and the totals count those approvals. A rule option that requires an approval on the merged version is on the parking list.
- **S0-7 (split):** for the pattern, any bot that opens a pull request is the automated side ("Agent and person"). "AI shown" is yes only for the fixed list of coding agents, declared accounts and commit markers. A dependency bot's row reads: bot, AI not shown. Pattern 2 is reworded to match (`docs/decisions.md`, S0-7).

## Not proven, and why

- A person who switches auto-merge on and then merges by hand looks the same as auto-merge. Proving it needs a write to a repository; it goes in the record's limits.
- A program that merges through an account of type `User` looks like a person merging by hand, unless the settings declare that account agent-operated (row 6).
- How far back the activity history goes: not documented; seen back to 8 Oct 2026 only.
- Commits with no linked account: none in Hevelius's data. Under A10 they change nothing, because no commit field makes a builder.
