## Decisions for the owner

Each has my lean; reply with the numbers ("S0-1A, S0-2A, …").

**S0-1. Where the list of changes comes from.**
- **A:** the pull-request list joined with the default branch's activity history. A change is a merged pull request, or a commit brought by a `push` or `branch_creation` entry that is not part of a pull request's merge. The walk of `main` stays as a cross-check, and any commit neither explains gets a "not covered" line. Where the activity history does not reach back to the period's start (its retention is not documented), that repository gets a "not covered" line for the gap. It survives aschecked's rewrite (124 of 124 matched), and the account that pushed comes from an authenticated action. **Lean.**
- **B:** the requirements' method: a walk of `main`'s first-parent line plus the pull-request list. It lists aschecked's 8 changes twice, and so fails "exactly once" on Hevelius's own data.

**S0-2. Force pushes in the period.**
- **A:** listed in their own section, "History rewritten": the time and the account. The commits a force push brings are not counted as changes, and the record says so. **Lean.**
- **B:** every commit a force push brings counts as a direct push (aschecked would gain about 80 rows).

**S0-3. The exact rule for A10.**
- **A:** logins are printed only from these authenticated actions: opening the pull request, merging it, reviewing it, switching auto-merge on, adding it to a merge queue, and pushing to the default branch (the activity history's account). A commit's author and committer fields, and any login GitHub links to them, are never printed. They are read only as AI markers: a `Co-Authored-By` line, or an author name, that matches the fixed list of coding agents in row 5. Bots are recognised by account id, not by login text. **Lean.**
- **B:** as A, without the pusher; direct pushes show no login.

**S0-4. What a change with no pull request shows.**
- **A:** one row per commit, as in example `a1b2c3d`. The builder is "no pull request: not shown". "Pushed by" is the account in the activity history. This includes each repository's first push. **Lean.**
- **B:** one row per push.

**S0-5. Which checks count as "on the merged version".**
- **A:** check runs and commit statuses on the pull request's last commit that started before the merge. Where a check of one name ran more than once, the last run is shown. **Lean.**
- **B:** all runs on that commit, including those started after the merge, each shown.

**S0-6. Approvals given on an earlier version.**
- **A:** an approval that is not dismissed counts for the pattern, and the row says "on an earlier version" when its commit is not the merged one. **Lean.**
- **B:** only an approval on the merged version counts for the pattern.

**S0-7. A bot that is not an AI tool opens a pull request (for example a dependency updater).** The requirements count any bot opener as "AI shown".
- **A:** keep that as written. The row shows the account type "bot", and the limits section says that "AI shown" includes automation. **Lean.**
- **B:** only bots on the fixed list, or declared accounts, count.
